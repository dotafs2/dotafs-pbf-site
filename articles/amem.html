A-MEM

A-MEM: Agentic Memory for LLM Agents

论文信息与原文

Wujiang Xu · Zujie Liang · Kai Mei · Hang Gao · Juntao Tan · Yongfeng Zhang

NeurIPS 2025 · arXiv v11 · 2025-10-08 · 原论文 · 作者代码

A-MEM 处理的是记忆怎么存、怎么关联、怎么更新。新内容进来后，先整理成 note，再找可能有关的旧 note，让 LLM 判断联系。新信息也可能改变对旧记录的理解。论文 §3

下面用一个虚构的文档搜索程序作例子，三条日志都是教学样例：

时间 日志
第一天 搜索“模型更新”，没有找到那篇增量训练文档，原因还没确认。
第二天 准备补充关键词和向量检索，检查是不是不同措辞导致漏搜。
第三天 检查导入清单后发现，那篇文档没有进入索引。补录后，原查询能找到它。

这三条记录有先后，也有解释上的变化。只把它们分别放进数据库，回答问题时可能只取到第二条，误以为原因已经确定是词语匹配。A-MEM 提供了重新组织这些记录的方法。

1. Note construction

论文把一条记忆表示为：

mi={ci,ti,Ki,Gi,Xi,ei,Li}m_i=\{c_i,t_i,K_i,G_i,X_i,e_i,L_i\}mi​={ci​,ti​,Ki​,Gi​,Xi​,ei​,Li​}

这里保存的不只是原内容，还包括时间、检索用的描述和关联记录。第一天的日志可以整理成下面这样：

字段 含义 例子
cic_ici​ 原内容 搜索“模型更新”，没有找到那篇增量训练文档，原因还没确认。
tit_iti​ 时间 第一天
KiK_iKi​ 关键词 模型更新、增量训练、搜索失败
GiG_iGi​ 分类标签 文档搜索、排查记录
XiX_iXi​ 上下文解释 一次未找到预期文档的查询，根因尚未确定。
eie_iei​ 文本向量 由编码器计算
LiL_iLi​ 关联的 note 初始为空，后面再找

关键词、标签和上下文解释可以由 LLM 生成。原内容和解释放在不同字段里，后面才容易检查解释是否准确。论文 §3.1、式 (1)–(2)

比如第一天没有查到文档，可以记成“查询失败”。但不能直接写成“检索算法有缺陷”，因为日志还没给出这个原因。

2. Embedding

A-MEM 将原内容和生成的描述一起编码，论文式 (3) 是：

ei=fenc(concat⁡(ci,Ki,Gi,Xi))e_i=f_{\mathrm{enc}}\bigl(\operatorname{concat}(c_i,K_i,G_i,X_i)\bigr)ei​=fenc​(concat(ci​,Ki​,Gi​,Xi​))

concat⁡\operatorname{concat}concat 把这些文字拼起来，fencf_{\mathrm{enc}}fenc​ 是文本编码器，输出向量 eie_iei​。论文式 (3)

原日志可能只写“搜不到”。补上关键词和上下文，后面用“查询失败”或“文档索引”搜索时，就多了一些可匹配的信息。

代价是：生成的描述如果写错，也会影响检索。不能因为文字是模型整理出来的，就默认它比原记录更可靠。

3. Link generation

每加一条新记忆，都让 LLM 读完所有旧记录，成本会随资料量增加。A-MEM 先用向量选候选，再让 LLM 检查联系。

论文式 (4) 使用 cosine similarity：

sn,j=en⋅ej∥en∥∥ej∥s_{n,j}=\frac{e_n\cdot e_j}{\lVert e_n\rVert\lVert e_j\rVert}sn,j​=∥en​∥∥ej​∥en​⋅ej​​

ene_nen​ 是新记忆的向量，eje_jej​ 是某条旧记忆的向量。点积除以两者长度，得到方向上的相似程度。论文 §3.2

用两个很小的向量算一下：

a=(1,0),b=(2,0),c=(0,1)a=(1,0),\quad b=(2,0),\quad c=(0,1)a=(1,0),b=(2,0),c=(0,1)

aaa 和 bbb 同方向，余弦相似度是 111；aaa 和 ccc 垂直，相似度是 000。这里的数字只是数学例子，真实文本向量由编码器产生。

取相似度最高的 kkk 条，就是 top-k 候选。接着把新 note 和这些候选交给 LLM，分析是否有共同主题、后续解释或其他联系。

回到日志：第二天的“补向量检索”和第一天的“没有搜到文档”有关，但前者仍然是一个待验证方案。第三天的导入检查才补上了实际原因。

如果要把它们画出来，可以这样标注关系：

第一天：没有搜到文档
  ├─ 第二天：尝试解释与待验证方案
  └─ 第三天：后续检查确认文档漏导入

关系类型和原句引用是这里建议的记录方式，论文中的关联集合本身并不保证这些关系都被正确验证。相似度为 0.80.80.8，也不能解释成“有 80% 的概率是因果关系”。

4. Memory evolution

第三天的新日志进入后，第一天的原话仍然成立：当时确实没有找到文档。但现在可以补充解释——后来确认那篇文档没有入库。

A-MEM 会用新记忆和相关旧记忆，判断是否更新旧 note 的上下文、关键词和标签。论文称这个过程为 memory evolution。论文 §3.3

按例子来看：

内容 第一天 第三天之后
原日志 没有找到文档，原因未确认 保留原文
上下文解释 一次原因未知的查询失败 后续检查确认与文档漏导入有关
关联 暂无 指向第三天的导入检查记录

第二天的方案也应该保留。它说明当时考虑过什么，不能把它改写成已经实施成功的修复。

实际做系统时，可以给解释加版本和来源。这样查询“第一天知道什么”时，仍然能还原当时的状态。这是针对时间回溯的工程补充，不能默认 memory evolution 已经处理好了所有历史版本问题。

这一步更新的是外部 note。LLM 参数有没有训练，是另一件事。

5. 回答问题时怎么取

当问题是“这次为什么没搜到文档”，先用同一个编码器得到问题向量，再按相似度取相关 note，放进回答上下文。论文也描述了关联记忆的访问；实际提供多少关联内容，需要控制上下文预算。论文图 2、§3.4

下面是这个例子的教学流程：

为什么没搜到文档？
  → 找到第一天的失败记录
  → 检查后续关联
  → 读第三天的导入结果
  → 根据记录回答：文档没有进入索引，补录后原查询可用

如果只读第二天的方案，可能答成“因为缺少向量检索”。所以连线有用的地方，是能把后来的检查结果带回来，而不是只返回措辞相似的记录。

6. 实验结果

论文在长期对话问答任务上评估记忆系统。看 Table 1 中使用 GPT-4o 的两项结果：

问答类型 LoCoMo 基线 F1 A-MEM F1
时间推理 9.09 39.41
单跳问答 61.56 48.43

这一组里，时间推理改善，单跳问答反而下降。说明组织和检索记忆的方式会影响不同类型的问题，不能只拿一个提高的数字判断整体效果。论文 Table 1

F1 在这里是答案与参考答案的词语匹配指标，不代表关系被正确理解的概率。记忆问答做得更好，也不等于训练出了完整人格。

可以用前面的三条日志做一个很小的检查：

  1. 只加入前两天，问原因。合理的回答应该保留“尚未确定”。
  2. 加入第三天，再问原因。回答应该能引用导入检查。
  3. 问“第二天是否已经修复”。记录里只有准备做，不能回答已经完成。

这能分别检查：是否把猜测写成事实、后续信息有没有起作用、计划和结果有没有混淆。

7. 和 LaMP 怎么接

组合两篇的思路，可以得到下面这个结构：

新记录
  → 建 note
  → 找相关旧 note
  → 建立联系、更新解释       A-MEM
  → 存入记忆库

新问题
  → 检索相关记录
  → 组装 prompt              LaMP 的 IPA 思路
  → LLM 生成回答
  → 用留出的答案检查效果

这是组合方案，不是两篇论文已经联合验证过的实现。可以先固定 LLM，单独比较普通记录检索和带关联、更新的记忆检索，看错误到底少在哪里。
